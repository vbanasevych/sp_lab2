# Профілювання та Оптимізація (Множення матриць)

Цей документ містить ключові тези та результати порівняння неоптимізованої (`-O0`) та оптимізованої (`-O3`) версій програми множення матриць.

## 1 & 4.3. FlameGraph (Аналіз графіків)

*   **1.1. Як будували:** Спочатку використовувався `perf record` для збору стеків викликів програми, після чого дані оброблялися скриптами `stackcollapse-perf.pl` та `flamegraph.pl` для генерації SVG.
*   **1.2. Результати до оптимізації (O0):** Графік `flamegraph_O0_3.svg` має "багатоповерхову" структуру з високими вежами. Це візуалізує те, що програма витрачає багато часу на системні виклики доступу до пам'яті всередині циклів, зокрема на виклики функцій `std::vector::operator[]` та `std::vector::size()`.
*   **1.2. Результати після оптимізації (O3):** Графік `flamegraph_O3.svg` став абсолютно плоским. Усі "вежі" зникли, оскільки 99.92% часу процесора виконується безпосередньо корисна робота у функції `multiplyMatrices` без жодних накладних викликів.

## 2 & 4.2. Статистика виконання (Час та процесор)

*   **2.1. Утиліта `time`:** Неоптимізована версія виконувалася близько 2 хвилин 11 секунд (130.87 секунд user time). Оптимізована версія завершила роботу всього за 13.57 секунд (13.46 секунд user time).
*   **2.2. Статистика `perf stat`:** Підтверджує колосальну різницю: час виконання впав з ~124.46 секунд для O0 до ~11.93 секунд для O3.
*   **2.3. Звіт `perf report`:** В O0 левова частка викликів всередині `multiplyMatrices` (яка займає 93.57% загального часу) дробиться на виклики `operator[]` (до 7.36% на один виклик) та `size()` (до 3.18%). В O3 ці дочірні виклики відсутні в репорті взагалі.

## 3 & 4.4. Енерговитрати (Power Consumption)

*   **3.1. Замір системи:** Для вимірювання базового споживання всієї системи використовувалася утиліта `powerstat`.
*   **Порівняння потужності (Ватти):** Середнє споживання системи під час виконання O0 становило 0.79 Ват. Під час виконання O3 середнє споживання ледь помітно зросло до 0.80 Ват.
*   **Пояснення енерговитрат:** Оптимізована програма сильніше і щільніше навантажує обчислювальні блоки процесора (використовуючи векторні інструкції), тому миттєва потужність ($P$, у Ватах) є трохи вищою.

## 4.1. Порівняння асемблерного коду до (-O0) та після (-O3) оптимізації

Аналіз згенерованого асемблерного коду (наприклад, через Compiler Explorer / Godbolt) наочно демонструє, як компілятор пришвидшує програму:

*   **Наявність накладних витрат (O0):**
    У версії без оптимізації для кожного кроку циклу процесор змушений робити дорогі системні виклики. В асемблерному лістингу O0 ми бачимо безперервні виклики методів вектора:
    `call "std::vector<...>::operator[](unsigned long) const"`
    Процесор постійно записує дані в стек (`mov DWORD PTR [rbp-12], 0`) і читає їх звідти, що робить роботу з пам'яттю надзвичайно повільною.
*   **Inlining та прямий доступ до пам'яті (O3):**
    У версії з оптимізацією `-O3` **повністю відсутні інструкції `call`**. Компілятор застосував *Inlining* — вбудував код методів `operator[]` безпосередньо в тіло циклу.
    Замість виклику функцій компілятор обчислює адреси напряму через зміщення вказівників у регістрах (Pointer Arithmetic):
    `mov rcx, QWORD PTR [rax]`
    `add rsi, 8` (перехід до наступного елемента типу double, який займає 8 байт).
*   **Розгортання циклів (Loop Unrolling):**
    Внутрішній цикл у версії O3 (`.L3`) став максимально компактним — у ньому лише 8 інструкцій, які напряму завантажують дані, множать, додають і порівнюють лічильник.

## 4.1.1. Інструкції AVX (SIMD) розширень

Оптимізація `-O3` (особливо з прапорцем `-march=native`) дозволяє компілятору задіяти сучасні векторні розширення процесора для паралельних обчислень.

*   **У неоптимізованому коді (O0)** математика виконується базовими скалярними інструкціями співпроцесора:
    `mulsd xmm0, QWORD PTR [rbp-48]`
    `addsd xmm0, QWORD PTR [rbp-48]`
*   **В оптимізованому коді (O3)** з'являються інструкції з префіксом **`v`** (VEX-кодування, що вказує на використання розширень AVX):
    `vxorpd xmm1, xmm1, xmm1` (швидке обнулення регістра)
    `vmovsd xmm0, QWORD PTR [rcx+rsi]`
    `vmulsd xmm0, xmm0, QWORD PTR [rdx-8]`
    `vaddsd xmm1, xmm1, xmm0`
